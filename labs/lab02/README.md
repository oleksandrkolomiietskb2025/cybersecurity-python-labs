# Лабораторна робота №2 — Варіант 12

**Тема:** Розробка консольних утиліт для задач кібербезпеки
**Завдання 2:** Аналізатор заголовків електронної пошти та фішингових індикаторів

## Встановлення залежностей

З кореня репозиторію, в активованому віртуальному середовищі:

```bash
pip install -r requirements.txt
```

Залежностей, крім стандартної бібліотеки Python та `ruff`, не потрібно.

## Структура файлів варіанту

```
labs/lab02/data/data_v12/
├── mail_headers.log        # дамп заголовків 6 тестових листів
└── suspicious_keywords.txt # словник стоп-слів для теми листа
```

Формат `mail_headers.log`: блоки заголовків одного листа, розділені рядком
`--- MESSAGE ---`. Кожен блок містить поля `Message-ID`, `From`, `Return-Path`,
`Reply-To`, один чи декілька рядків `Received`, та `Subject`.

## Запуск

Команди виконуються з кореня репозиторію через `python -m ...`.

### Демонстрація Завдання 1 (ООП)

```bash
python -m labs.lab02.main demo
```

Показує: успішний/невдалий вхід, валідацію email, права адміністратора,
завершення сесії за таймаутом, вихід із системи, журнал аудиту.

### Аналіз пошти на фішинг (Завдання 2)

```bash
python -m labs.lab02.main analyze \
    --mail-log labs/lab02/data/data_v12/mail_headers.log \
    --suspicious-keywords labs/lab02/data/data_v12/suspicious_keywords.txt \
    --out-csv labs/lab02/data/data_v12/phishing_report.csv
```

Або напряму, без `main.py`:

```bash
python -m labs.lab02.task2 \
    --mail-log labs/lab02/data/data_v12/mail_headers.log \
    --suspicious-keywords labs/lab02/data/data_v12/suspicious_keywords.txt \
    --out-csv labs/lab02/data/data_v12/phishing_report.csv \
    --debug
```

## Опис параметрів CLI (Завдання 2)

| Параметр | Обов'язковий | Опис |
|---|---|---|
| `--mail-log` | так | Шлях до файлу з дампом заголовків листів |
| `--suspicious-keywords` | так | Шлях до словника стоп-слів (по одному слову на рядок) |
| `--out-csv` | ні | Шлях для збереження детального CSV-звіту |
| `--debug` | ні | Вмикає DEBUG-рівень логування (деталі парсингу) |

## Поведінка при помилках

- Якщо `--mail-log` або `--suspicious-keywords` вказують на неіснуючий файл —
  логується помилка (`logging.error`), аналіз продовжується з порожніми
  вхідними даними (список листів або словник стоп-слів буде порожнім), падіння
  програми не відбувається.
- Якщо директорія для `--out-csv` не існує — створюється автоматично.
- Якщо запис CSV-файлу неможливий (немає прав доступу) — помилка логується,
  консольний звіт при цьому все одно виводиться.

## Логіка оцінки ризику листа

- Невідповідність домену `From` і `Return-Path` — +40 балів
- Невідповідність домену `From` і `Reply-To` — +20 балів
- Стоп-слова в темі листа — +10 балів за кожне, максимум +20
- Кількість проміжних вузлів `Received` > 4 — +20 балів (аномальна кількість ретрансляцій)
- Підсумковий бал обмежений 100; `>= 70` — CRITICAL PHISHING SUSPECT, `>= 40` — SUSPICIOUS, нижче — LOW RISK
